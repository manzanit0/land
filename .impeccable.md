## Design Context

### Users
A single user: the page's owner, a platform engineer at Docker. It is
their Firefox home/new-window page, glanced at many times a day between
tasks. The job to be done: triage GitHub pull requests in seconds
(what can I merge, what is stuck, what needs my review) and jump to
frequently used links. Zero onboarding needed; the user built it.

### Brand Personality
Quiet utilitarian. Calm, dense, information-first — like a well-kept
terminal or dashboard. It should get out of the way; no greetings, no
decoration for its own sake. Emotional goal: instant orientation and a
small sense of order.

### Aesthetic Direction
Restrained dashboard aesthetic. Follows the system light/dark theme.
GitHub-adjacent status colors (green = mergeable, amber = waiting,
purple = review requested) are meaningful, not decorative.
Anti-references: flashy startup landing pages, glassmorphism, gradient
text, hero metrics.

### Design Principles
1. Glanceable first: counts and statuses readable in under a second.
2. Density over whitespace: this is a work tool, not a brochure.
3. Every color carries meaning; no decorative accents.
4. Self-contained single file; no external assets beyond the GitHub API.
5. Fail quietly and visibly: errors and empty states in place, never
   blocking the rest of the page.
